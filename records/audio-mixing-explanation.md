모노가 스테레오로 확장하는경우 오디오 버퍼 믹스를 어떻게 할것인가?

### 모노 → 스테레오 확장 예시

```javascript
// 버퍼: 모노 (1채널만 있음)
//   채널0: [0.5, 0.3, 0.1]  ← 이게 "마지막 채널"

// maxChannels = 2 (스테레오로 믹싱해야 함)
```

### 처리 과정

```typescript
for (let channel = 0; channel < 2; channel++) {
  // channel: 0, 1
  const sourceChannel = buffer.getChannelData(
    Math.min(channel, buffer.numberOfChannels - 1)
    // Math.min(channel, 1 - 1) = Math.min(channel, 0)
  );
}
```

- `channel = 0`:
  - `Math.min(0, 0) = 0`
  - `getChannelData(0)` → `[0.5, 0.3, 0.1]` 사용
- `channel = 1`:
  - `Math.min(1, 0) = 0`
  - `getChannelData(0)` → 같은 `[0.5, 0.3, 0.1]` 재사용

### 결과

```
mixedBuffer:
  채널0 (Left):  [0.5, 0.3, 0.1]  ← 원본 모노
  채널1 (Right): [0.5, 0.3, 0.1]  ← 같은 데이터 재사용
```

모노 신호가 양쪽 채널에 동일하게 들어갑니다.

## 시각적 설명

```
원본 모노 버퍼:
┌─────────────┐
│ 채널0: [0.5, 0.3, 0.1] │  ← 이게 "마지막 채널"
└─────────────┘

스테레오로 확장:
┌─────────────┐  ┌─────────────┐
│ 채널0: [0.5, 0.3, 0.1] │  │ 채널1: [0.5, 0.3, 0.1] │
└─────────────┘  └─────────────┘
     ↑                    ↑
  원본 사용          같은 채널 재사용
```

## 다른 예시: 스테레오 → 5.1 서라운드

```javascript
// 버퍼: 스테레오 (2채널)
//   채널0: [0.5, 0.3]
//   채널1: [0.4, 0.2]  ← 이게 "마지막 채널"

// maxChannels = 6 (5.1 서라운드)
```

처리:

- `channel 0, 1`: 정상 사용
- `channel 2, 3, 4, 5`: `Math.min(2~5, 1) = 1` → 채널1 재사용

결과:

```
채널0: [0.5, 0.3]  ← 원본
채널1: [0.4, 0.2]  ← 원본
채널2: [0.4, 0.2]  ← 채널1 재사용
채널3: [0.4, 0.2]  ← 채널1 재사용
채널4: [0.4, 0.2]  ← 채널1 재사용
채널5: [0.4, 0.2]  ← 채널1 재사용
```

## 핵심 포인트

"마지막 채널"은 `buffer.numberOfChannels - 1`을 의미합니다.

- 모노(1채널): `1 - 1 = 0` → 채널0이 마지막
- 스테레오(2채널): `2 - 1 = 1` → 채널1이 마지막
- 5.1(6채널): `6 - 1 = 5` → 채널5가 마지막

요약: 채널 수가 부족할 때 존재하는 마지막 채널을 재사용해 확장합니다.

## DataView 한눈에 정리 (WAV 헤더 작성 맥락)

- **정의**: ArrayBuffer 위에서 바이트 단위로 여러 숫자 타입(8/16/32비트, 부호/무부호, float)을 읽고/쓸 수 있게 해 주는 뷰. 엔디안(리틀/빅)도 지정 가능.
- **왜 쓰나?** WAV 같은 바이너리 포맷은 “정확한 오프셋+엔디안”으로 값을 넣어야 함. TypedArray는 타입·엔디안이 고정이라 헤더처럼 여러 타입을 섞어 쓸 때 불편 → DataView로 해결.
- **핵심 API**:
  - 쓰기: `setUint8/16/32`, `setInt16/32`, `setFloat32/64` (마지막 인자 `true`면 리틀엔디안)
  - 읽기: `getUint8/16/32`, `getInt16/32`, `getFloat32/64`
- **WAV 헤더에서의 실제 사용**:
  - `writeString(view, 0, 'RIFF')` → 문자열을 바이트로 기록
  - `view.setUint32(4, totalSize - 8, true)` → 32비트 정수(리틀엔디안)로 파일 크기 기록
  - `writeString(view, 8, 'WAVE')`, `writeString(view, 12, 'fmt ')` → 섹션 식별자 기록
  - `setUint16/32`로 채널 수, 샘플레이트, byte rate, block align, bits per sample 등을 규격 오프셋에 기록
- **엔디안 주의**: PCM WAV는 리틀엔디안이 표준 → `setXXX(..., true)` 사용.
- **요약**: DataView = “바이트 단위 정밀 제어용 도구”. 바이너리 헤더/포맷을 직접 쓸 때 필수.
